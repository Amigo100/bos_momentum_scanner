## §1 Lifecycle staging — S0–S4 (replaces the freetext stage guess)

| Stage | Observable definition | Hunting posture |
|---|---|---|
| **S0 PRE-WAVE** | Mechanism exists in lab/pilot; no firm *paid* demand; capital = grants/seed; ≤1 precursor (§2) firing | Log in discovery_log as *monitor*; no vehicle mapping yet |
| **S1 IGNITION** | **≥2 of P1–P3 evidenced and dated inside 12 months, AND P4 holds** (public pure-plays not re-rated) | **The target zone.** Build the value-chain map + benchmark set NOW, before the legibility event; hunt any constituent that flags |
| **S2 PUBLIC INFLECTION** | Leaders printing backlog/revenue acceleration AND re-rating; dispersion wide (leaders rewarded, also-rans not); first initiations | Hunt the converters; run the §4 bottleneck-migration sweep for the next underpriced rung |
| **S3 INSTITUTIONALIZATION** | Indiscriminate sympathy moves appearing; ETF filings/launches; issuance into strength; laggards bid | Recognition-gate territory: hunt only decoupled leaders / genuinely-early sub-themes (the 0c escapes) |
| **S4 SATURATION / DIGESTION** | The closed-froth test met, or capex-digestion language, or TD triggers firing | STAND-DOWN / retire per the existing 0c gates |

**Transition markers.** S1→S2: the first public-name print that *converts* a precursor (award→backlog,
backlog→revenue). S2→S3: ≥2 closed-froth confirmers present while the indiscriminate re-rate is still
absent. S3→S4: the existing recognition-closed test (unchanged — still the only theme cut).
**Compatibility:** the legacy `stage` field keeps `early/mid/late` (derive S0/S1→early, S2→mid,
S3/S4→late); the precise read goes in the additive `stage_scurve` field.

## §2 Inflection precursors — P1–P4 (each needs DATED, SOURCED evidence)

- **P1 — Capital-formation dislocation.** Private/VC/state capital concentrating into the mechanism:
  ≥2 marquee rounds, or a ≥2x valuation step-up, inside 12 months — **while listed pure-plays have
  not re-rated.** The *dislocation* between private marks and public prices is the signal, not the
  rounds alone.
- **P2 — Capability/cost-threshold cadence.** A measurable tech curve approaching a commercial or
  legibility threshold, with the **interval between credible milestones compressing** (an interval
  halving = firing).
- **P3 — Anchor-demand event.** The first firm, named, **paid** demand: an FFP contract, enacted
  procurement, a paid offtake/API at scale. LOIs / MOUs / reservations do not count (same bar as
  DNA §7).
- **P4 — Recognition still open.** Thin/no coverage; pure-plays flat-to-down LTM despite mechanism
  news; no dedicated ETF; the theme absent from sell-side frameworks.

Record as a count with members — `precursors 3/4 (P1, P3, P4)` — plus one dated, sourced line per
firing precursor. **S1-IGNITION = ≥2 of P1–P3 + P4 holds.**

## §4 The bottleneck-migration method (general; run weekly per active wave)

"GPUs → power → cooling → memory" is one instance. The method:

1. **Write the constraint chain.** For every active wave (HUNT/HOLD with rising capex), write the
   value chain as an ordered dependency chain from demand source to delivered capability. (AI-compute
   worked example: chips → advanced packaging → HBM → in-rack power → on-site generation → grid
   interconnect/transformers → cooling → shell/construction → skilled labor.)
2. **Locate the binding constraint NOW** by the scarcity signature — any 2+ of: lead times
   stretching · step-vendor pricing/spreads rising · book-to-bill >1 across the step's vendors ·
   customers pre-paying or vertically integrating · expedite fees / second-source qualification.
3. **Predict the NEXT constraint.** When the current constraint's relief is *dated* (capacity adds
   with COD/ramp schedules), demand transmits to the step ranking worst on: (i) longest
   capacity-addition lead time, (ii) least utilization headroom, (iii) most concentrated supply.
   Rank by time-to-relief at the current step vs time-to-build at the candidate step.
4. **The trade.** The market prices the *current* constraint (those vendors re-rated); next-constraint
   vendors still trade as cyclicals → **birth a sub-theme entry at S1, surfaced-via
   `bottleneck-migration`**, whenever an investable small-cap expression exists.
5. **Falsifiers.** A chain is only as alive as its source demand — upstream fade is TD-3 for every
   link; substitution/tech bypass kills a single step.

**Persistence:** each parent theme carries an additive `constraint_chain` field — ordered steps, each
`{step, status: cleared|current|next|watch, evidence}` (one line each). 0b re-checks every chain
weekly for migration evidence; 0d favours the rung the stage implies.

**OPEN** (= P4 holds) → **CLOSING-early** (leaders re-rate on prints; first initiations; dispersion

## §6 NEW-CLUSTER lifecycle (bottom-up theme birth, with rules instead of vibes)

- **Birth:** ≥2 flagged names converging on one demand mechanism within a rolling 4-week window →
  write a `cluster-candidate` record to discovery_log: `{kind: cluster-candidate, mechanism,
  member_tickers (+dates), first_seen, weeks_tracked, corroborators, cluster_status}`.
- **Track:** every open cluster is explicitly re-tagged each weekly 0b pass
  (*monitor / promoted / discarded* + one-line reason). **Silent drops prohibited.**
- **Promote** (→ enters 0c as a candidate theme, still facing the eligibility gate) when ANY of:
  a 3rd independent name converges · a §3 leading indicator corroborates the same mechanism (VC
  round / enacted policy / anchor contract) · any member clears Tier 2 (the funnel itself confirming
  investability).
- **Discard** at 6 consecutive weeks with no new member, no corroborator, AND the original members'
  signals faded — `discarded` + reason, record retained. **Rebirth is free** (a re-fire reopens it);
  discard stays cheap to reverse, so recall is preserved.

## §7 Proxy quality + mapping confidence (two axes; grade them, don't vibe them)

**Proxy quality — "if the theme works, does THIS ticker's price capture it?"** Four checks:

1. **Revenue exposure** — % of revenue (or forward bookings if pre-revenue) tied to the mechanism:
   ≥50% (pure-play) · 20–50% · <20% or unquantifiable.
2. **Causal linkage** — named, verifiable demand pathway (firm orders *in the theme*) · customer-spend
   adjacency · sentiment/correlation only.
3. **Confounds** — other segments/drivers that swamp the theme: a mega-cap with a theme *slice* caps
   at **adequate** (the AXON rule); exposure via a minority stake in a private co is **weak** (the
   GXAI rule).
4. **Stage-fit** — the rung matches the theme's S-stage (§1/§4); a mismatch downgrades one notch.

**STRONG** = pure/majority exposure + named pathway + no swamping confound. **ADEQUATE** = real,
quantified but minority exposure, or cap-size dilution. **WEAK** = derivative / correlational /
unquantified / holding-structure exposure. (`unrated` only for themes born this week; resolve next
run.) Tier 2's "weak proxy for a strong theme is a DROP" reads **this** definition.

**Mapping confidence — "does this ticker belong to this theme AT ALL?"** (the false-match killer):

- **VERIFIED** — identity confirmed from a primary source (the company's own filing/IR describes the
  theme business), cited, this run or carried from a prior verification.
- **PROBABLE** — consistent secondary evidence; not yet primary-checked.
- **UNVERIFIED** — matched on name/sector/keyword only.

Rules: every **NEW** ticker→theme mapping gets one targeted identity check ("what does this company
do *now*, per its latest filing/IR") before it can be VERIFIED. **Only VERIFIED mappings may be
fast-tracked or listed as actionable benchmark matches** — UNVERIFIED still appears (recall), tagged,
for Tier 1 to check. A mapping that **fails** verification goes on the theme's additive
`false_matches` list (`{ticker, why, date}`) — **checked before every cross-reference**, so a false
match is rejected in one line forever instead of re-disproven weekly (CNM was re-verified twice in
two runs; that labor stops here).

## §8 Regime-shift → re-rank protocol (systematic, not ad-hoc)

- 0a names **1–3 `binding_axes`** each week — the specific reads that would change the posture if
  they crossed (e.g. "hike odds >50% by Dec", "HY OAS >350bp", "2y rolling over").
- **Material shift** := the posture lean changed (RISK-ON ↔ NEUTRAL ↔ RISK-OFF) OR the
  easing-inflection state changed (yes/near/no) OR a previously-named binding axis crossed. 0a
  outputs `regime_shift: none | minor | material` (+ which axes moved).
- On **material**: 0c step 1 performs a **mandatory full-map re-tag** — `regime_fit` re-derived for
  *every* tracked theme (not only the Δ-touched ones), then the HUNT set re-tiered (P1/P2/P3), with
  `regime_retag: full @<date>` noted in theme_map meta. On minor/none: the standard Δ refresh.
  (The 2026-06-08 energy-shock + hawkish-hold flip did this by improvisation; this makes it the rule.)
- **DNA guard:** a re-tag moves tiers and hunting priority only — it never STAND-DOWNs (the
  recognition gate owns that), never blocks a flagged name, never changes size (there is none), and
  never sells (exits are the scanner's).
